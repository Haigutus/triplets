triplets.validation package¶

Submodules¶

triplets.validation.context module¶

Context enrichment for violations frames, a separate call after validation.

enrich adds human/schema context columns to the canonical violations frame: what a finding found in the data (TARGET), which instance/file the object came from, what the object is, what the shape says about itself, and what the export schema defines for the class and attribute. Every source is optional — absent sources leave their columns null, so the output schema is stable. concat_violations joins the frames of several validation runs.

All lookups are vectorized maps built once from the sources — cost is O(data), not O(violations × data).

triplets.validation.locations module¶

Exact source locations for violations — one grep-style pass over the CIM/XML.

RDF objects carry no text coordinates through the triplets frame, so locations are recovered from the original files at export time: each source file is read once and every rdf:ID / rdf:about definition is indexed with its line number — one sequential pass per file, cost independent of how many IDs are wanted. For each violation, the violated property’s own position is then searched inside that object’s text window, so the annotation lands on the offending property element, not just the object.

locate_violations is the public pass: it stamps LOCATION_COLUMNS (SOURCE_URI, SOURCE_LINE, SOURCE_SNIPPET — the located line’s text) onto a violations frame — both the SARIF and the sh:ValidationReport exports call it when given sources=, and it is exposed as violations.shacl.locate(sources=...).

The parse/validate hot paths are untouched: nothing here runs unless sources are handed to an export. When the same object is defined in several files (rdf:about continuation across profiles), the first definition wins — a violated KEY living in a later profile file falls back to the definition position. Positions are whole lines (1-based), deliberately: RDF text serializations put one statement per line, so the line IS the reference — columns add per-format anchor rules (byte vs UTF-16 units, element shapes) and broke SARIF viewers, for no extra information. Line-only is also what keeps the pass extensible beyond XML: IDs and KEYs appear as literal substrings in every serialization (N-Quads, Turtle, JSON-LD).

triplets.validation.sarif module¶

SARIF 2.1.0 export of validation results.

Turns the canonical violations frame into a SARIF log any SARIF consumer can ingest (GitHub, SonarQube, VS Code viewers, …). Grouping is the default: a model with 100k identical findings is one issue — one result per rule with occurrenceCount and sample instances (first 3 + last 3) — so reports stay reviewable; group=False emits one result per violation.

RDF objects have no text coordinates, so results point at the model through logicalLocations (object id / type / name) plus the source file as artifactLocation when the enrichment pass can trace it. Passing data/shapes/rdf_map runs that pass automatically (see context.enrich).

triplets.validation.schema_ir module¶

Schema-based validation: compile the export schema (rdf_map) into engine IR — cardinality, datatypes and enumerations (compile_schema) and the reference types of associations (compile_references), validated by the same vectorized engines that run SHACL shapes.

compile_schema compiles the profiles of an rdf_map_scope, merged into one (triplets.validation.schema_scope): a CGMES 3.0 EQ file is ["EQ", "OP", "SC"]. One profile = that profile’s own rules.

The IR keeps the engines’ sh:* dispatch keys (registries stay shared); results present with vocabulary-accurate types instead — schema validation does not masquerade as SHACL (constraint language "rdfs"):

sh:minCount → xsd:minOccurs sh:maxCount → xsd:maxOccurs sh:datatype → xsd:type sh:in → rdfs:range sh:closed → schema:domainIncludes triplets:range → rdfs:range triplets:missing (a reference to an object not in the data)

Cardinality comes from the schema’s already-resolved xsd:minOccours / xsd:maxOccours fields, datatypes from xsd:type expanded by the schema’s prefixes: an XSD type is checked as such; any other (cim:ActivePower) by the XSD type of its own datatype entry (dataType, else the IRI’s local name — the CIMDatatype entry a bundle carries); a type without one is listed in skipped_shapes, not checked. Enumeration membership comes from values. Class rules never widen to subclasses: each Class entry already lists its inherited attributes. No rdflib on this path: graph is None and the pyshacl engine refuses schema-compiled shapes.

triplets.validation.schema_scope module¶

The export-schema scope of a validation run: which profiles of an rdf_map it uses, merged into one, and the class inheritance they declare.

rdf_map_scope names profiles by section key ("EQ") or by any identifier the profile declares (keyword / versionIRI / profileVersionIRI / conformsTo), mixed, in any sequence. None is the rdf_map’s root entries (an unsectioned, hand-made schema; a sectioned bundle has none). "*" is every section.

Listed profiles are merged into one, never stricter than the profiles run one by one — triplets._header.merge_sections() holds the rules: a CGMES 3.0 EQ file is ["EQ", "OP", "SC"]. A run logs each datatype conflict as an error and one warning for the relaxed constraints; the notes become the run’s skipped_shapes (not checked) and relaxed_constraints (checked, more loosely).

triplets.validation.shacl_duckdb module¶

SHACL DuckDB engine — compiled-IR executor for larger-than-memory data.

Every constraint compiles to one SQL query against the connection’s configured triplets table ([ID, KEY, VALUE, INSTANCE_ID]), so validation streams through DuckDB’s vectorized executor and spills to disk instead of requiring the dataset in RAM. Input is a DuckDB connection holding the table (con.read_rdf(...)); any other flavor (pandas/polars/arrow) is registered into an in-memory connection, which makes the engine uniformly testable.

Semantics are identical to the pandas/polars engines (same IR, same canonical violations schema, same lexical-form datatype deviation). The nested and query components (sh:or, sh:and, sh:not, sh:node, sh:sparql) delegate to the pandas implementations — they materialize the (scoped) table, which is fine: those are a handful of rows even in the real profiles, and sh:sparql needs an rdflib graph anyway. SPARQL targets materialize it the same way: their focus IDs resolve through shacl_pandas.sparql_targets into the _shacl_targets table the SQL reads.

Explicitly selected (engine="duckdb"), not in the auto order: polars owns the in-memory fast path; this engine is the deliberate choice when the data does not fit.

triplets.validation.shacl_ir module¶

Compile SHACL shapes once into an engine-agnostic IR (constraint table).

rdflib is the definitive shapes parser: shapes are parsed exactly once into CompiledShapes — the shapes graph (consumed by the pyshacl reference engine) plus a flat constraint table (consumed by the pandas/polars/duckdb executors, which never touch rdflib). Compilation is cached by content hash, and each engine caches its own compiled artifact (LazyFrame plan builders, SQL) in CompiledShapes.plans — re-validating new data against the same shapes never recompiles anything.

IR: one row per shape x target x path x constraint component:

shape_id, shapes, target_on, target_by, path, inverse, via_type,
component, params, severity, message, name, description

params holds the component’s parameter: a scalar (sh:minCount), a list (sh:in), or nested row-dict lists (sh:or / sh:and / sh:xone / sh:not, and the rows of sh:node / sh:property). Unknown components are kept as rows and logged — engines skip what they don’t implement; pyshacl still covers the full spec. shapes is the row’s lineage — the shape ids whose sh:deactivated removes it; every shape compiles, and CompiledShapes.active() filters the switched-off ones.

triplets.validation.shacl_pandas module¶

SHACL pandas engine — compiled-IR executor (debugging reference for the vectorized engine family).

Operates directly on the triplet DataFrame’s raw string VALUEs — no rdflib, no rdf_map. That enables a deliberate deviation from pyshacl: the datatype check judges the actual lexical form. rdflib reads "1"^^xsd:float as simply valid; here it is reported, on two levels:

  • value outside the declared type’s lexical space (“abc” for xsd:float) → VIOLATION_TYPE sh:datatype, the shape’s declared severity

  • value valid but written in a non-canonical / narrower form (“1” for xsd:float — integer form; “0” for xsd:boolean) → VIOLATION_TYPE triplets:lexicalForm, severity Warning (lexical=False skips this level)

Structure: one pure function per constraint component (context, rule) → violations DataFrame, registered in CONSTRAINT_VALIDATORS. Every validator sees the rule’s path normalized to (FOCUS, PATH_VALUE) pairs — inverse paths (sh:inversePath) swap the columns, so direction is handled once in _Context.path_rows.

sh:sparql constraints are delegated to triplets.sparql (auto engine — qlever when built, else oxigraph, else rdflib): the engine loads the data once (content-hash cached), each constraint runs as one SELECT with the focus nodes bound via VALUES, and max_workers runs the constraint queries in parallel: forked processes on rdflib (copy-on-write shares the dataset; threads don’t help GIL-bound rdflib), threads on the embedded engines (they release the GIL while evaluating over one read-shared store). SPARQL targets run the same way, each distinct target query once per validation (sparql_targets — the polars and duckdb engines call it too).

Known limits:

  • sh:nodeKind — triplets store every value as a string, so term kind is decided like the N-Quads exporter decides it: by the schema when rdf_map names the path (a datatype key is Literal even when its values look like UUIDs), by value form otherwise (known ID / UUID / URI scheme / enum PhaseCode.ABC)

triplets.validation.shacl_polars module¶

SHACL polars engine — compiled-IR executor (performance).

Lazy by construction: every constraint becomes one LazyFrame plan against a shared base, and everything executes in a single polars.collect_all — parallel across plans, with common subplans (the per-path filters, the Type scan) eliminated once. Shared indices (per-class focus IDs, the set of all IDs) are materialized eagerly once and reused across plans — speed over memory, per the engine guidance in docs/validation.md. No Python UDFs, no per-constraint collects, no streaming.

Semantics are identical to the pandas engine (same IR, same canonical violations schema, same lexical-form datatype deviation — see shacl_pandas). The rare nested/query components (sh:or, sh:and, sh:not, sh:node, sh:sparql — a handful of rows even in the real profiles) are delegated to the pandas implementations, so coverage is complete while the hot path stays lazy. SPARQL targets resolve through shacl_pandas.sparql_targets once per run; their rules then plan like any other.

Per-rule plan builders are cached in CompiledShapes.plans["polars"] — the IR is split and normalized once per compiled shapes, then only re-bound to new data.

Note: sh:pattern runs on Rust regex (no lookarounds). The ENTSO-E profiles use plain character-class patterns; exotic patterns belong to pyshacl.

triplets.validation.shacl_report module¶

Map a pyshacl/SHACL ValidationReport graph to the canonical violations DataFrame, and the inverse: export a violations DataFrame as a standard sh:ValidationReport.

Canonical violations schema (identical across all current and future SHACL engines, so the later vectorized engines can produce it natively):

[ID, KEY, VALUE, VIOLATION_TYPE, MESSAGE, SEVERITY, SOURCE_SHAPE]

triplets.validation.shacl_report.violations_to_report_graph(violations, report_source=None, report_references=None, rdf_map=None, undefined_namespace='http://iec.ch/TC57/CIM100#')[source]¶

Violations DataFrame → sh:ValidationReport rdflib graph (inverse of report_to_violations; KEYs expand through the export schema namespaces — rdf_map — undefined_namespace for names it lacks, unless already URIs).

A result carries several plain-text sh:resultMessages when the frame has the context/location columns: the engine message, the shape and schema descriptions (context.enrich) and the source position (locations.locate_violations) — SHACL has no location vocabulary, so a message is the interoperable carrier.

Report-level metadata (always): prov:generatedAtTime, dcterms:creator (tool + version). Optional: dcterms:source / dcterms:references from report_source / report_references (str or sequence — validated file name(s) / shape file name(s)).

Defaults come from violations.attrs["validation"] — the metadata the validation functions stamp on the frame (timestamp of the validation run, tool version, data/shape file names). Explicit arguments override it.

[<language>_message] = the text is the shape’s/schema’s own message; [engine_message] = the engine worded it. the validation functions stamp MESSAGE_SOURCE on every row; frames without it fall back to the violation-type namespace (triplets:* → engine). Module contents¶

Validation over triplet data — three generic validations, scoped by the caller:

  • validate_shacl — SHACL shapes;

  • validate_schema — the export schema’s cardinality, datatypes and enumerations, per instance;

  • validate_schema_references — the reference types of associations, per source instance, against target instances and profiles.

Every input has a scope named after it: data + data_scope (INSTANCE_IDs), rdf_map + rdf_map_scope (profiles, merged — schema_scope). Nothing here reads instance headers; triplets.cgmes_tools.validate_by_header does. enrich adds the context columns in a separate call.

Engines (registry dispatch, mirroring triplets.parser / triplets.sparql):

  • pyshacl — reference, spec-complete, rdflib-based; always available with the validation extra

  • polars — compiled-IR executor (performance; one lazy plan per constraint, single collect_all; auto-preferred when polars is installed)

  • pandas — compiled-IR executor (debugging; same complete registry and semantics, eager. sh:sparql delegates to triplets.sparql with optional max_workers; sh:node runs the compile-time-expanded referenced shape against the value nodes (on a node shape, the focus node); sh:nodeKind is decided by the rdf_map schema)

  • duckdb — compiled-IR executor for larger-than-memory data (one SQL query per constraint against the triplets table, streams/spills via DuckDB; explicit engine=”duckdb”, not in auto — polars owns the in-memory fast path)

Compile once: compile(shapes) parses the shapes with rdflib exactly once into CompiledShapes (shapes graph + flat constraint table, cached by content hash). Engines receive the compiled object:

validate(data, compiled, rdf_map=None, data_scope=None, ancestors=None, **kwargs) → violations DataFrame

(rdf_map the scoped schema, ancestors the class_ancestors map.)

pyshacl consumes the graph; the vectorized engines consume the IR (and cache their own plan per engine in CompiledShapes.plans) — they never touch rdflib. sh:sparql IR rows and SPARQL targets are delegated to triplets.sparql by the vectorized engines (pyshacl evaluates both itself via advanced=True).

A deliberate deviation from pyshacl: the datatype check inspects the raw lexical form of VALUE (see shacl_pandas) — with lexical=True (default) every engine’s report carries the triplets:lexicalForm Warnings, with lexical=False none does.

triplets.validation.validate_shacl(data, shapes, rdf_map=None, data_scope=None, rdf_map_scope=None, engine='auto', lexical=True, undefined_namespace='http://iec.ch/TC57/CIM100#', inheritance=True, deactivated_shapes=None, abort_on_first=False, **kwargs)[source]¶

Validate triplet data against SHACL shapes; return a violations DataFrame.

Parameters:

  • data (triplet DataFrame (pandas/polars), arrow, or DuckDB connection)

  • shapes (str | path | list of paths | rdflib.Graph | CompiledShapes) – SHACL shapes (format auto-detected by extension). Pass the result of compile(shapes) to reuse the parsed shapes across validations.

  • rdf_map (dict or str, optional) – Export schema — xsd-typed literals in the data graph, the schema-driven sh:nodeKind decision and the class inheritance (see inheritance), from the profiles in rdf_map_scope.

  • data_scope (iterable of INSTANCE_ID, optional) – Validate only these instances’ named graphs — data outside the scope is not loaded, so references into unscoped instances count as absent. Include dependency instances in the scope (or validate the full union, data_scope=None) for cross-instance checks.

  • rdf_map_scope (profile identifier or sequence of them, optional) – The rdf_map profiles the run uses, merged into one: section keys ("EQ") and/or declared profile IRIs; "*" = every section; None = the rdf_map’s root entries. A scope without entries raises ValueError (see triplets.validation.schema_scope).

  • engine (str, default "auto") – “polars” (performance), “pandas” (debugging), “duckdb” (larger-than-memory) or “pyshacl” (reference). “auto” picks polars → pandas → pyshacl; duckdb is always an explicit choice.

  • lexical (bool, default True) – Report valid-but-narrower datatype forms ("1" for xsd:float) as triplets:lexicalForm Warnings — a deliberate deviation from pyshacl, see shacl_pandas. The vectorized engines check them inline, pyshacl gets the pandas datatype check as a supplement. False skips the check on every engine (pyshacl: the pure pyshacl report); values outside the lexical space stay sh:datatype violations.

  • undefined_namespace (str, default CIM100) – Namespace for names the schema does not declare (every name without an rdf_map) in the graph the sh:sparql constraints and pyshacl see.

  • inheritance (bool, default True) – sh:targetClass and sh:class also match instances of subclasses, from the scoped profiles’ inheritance lists (class_ancestors(); pyshacl: as rdfs:subClassOf in ont_graph). False matches the exact rdf:type only. No effect without an rdf_map.

  • deactivated_shapes (shape IRI or iterable of them, optional) – The shapes to switch off for this run — replaces the set the graph declares (compiled.deactivated): None = the declared set, [] = every shape runs, the declared ones included; extend or reduce it freely. The NC validation aggregates switch off different shapes of a shared base this way, and one compile serves every aggregate (CompiledShapes.active).

  • abort_on_first (bool, default False) – Stop at the first Violation — for a yes/no gate, not a full report. Warning and Info findings and triplets:invalidSparql rows never stop the run. The result holds the findings of the work finished before the stop, so engines agree on whether a Violation exists, not on the rows. polars / duckdb stop after the vectorized pass, pandas between rules, pyshacl after its first failing constraint (the lexical supplement is then skipped).

Notes

The returned frame carries the validation-run metadata in violations.attrs["validation"] (start/end timestamps and duration, engine, tool version, data/shape file names, shape and constraint counts, any shapes/components the run skipped, and aborted: True when abort_on_first met a Violation) — every report exporter reads it, so SARIF, the sh:ValidationReport and the csv/excel exports tell the same story.

triplets.validation.validate_schema(data, rdf_map, data_scope=None, rdf_map_scope=None, report_undefined_keys=False, engine='auto', undefined_namespace='http://iec.ch/TC57/CIM100#', severity='Violation', **kwargs)[source]¶

Validate triplet data against the export schema: cardinality, datatypes and enumerations of the scoped profiles, per instance.

Every instance in data_scope is validated on its own (cardinality never counts rows of another instance) against the profiles in rdf_map_scope, merged into one (triplets.validation.schema_scope). Class rules never widen to subclasses; references are checked by validate_schema_references.

data_scopeiterable of INSTANCE_ID, optional

The instances to validate; None = every instance in data.

rdf_map_scopeprofile identifier or sequence of them

Section keys and/or declared profile IRIs (["EQ", "OP", "SC"] for a CGMES 3.0 EQ file); "*" = every section; None = the root entries. A scope without Class entries raises ValueError.

report_undefined_keysbool, default False

Also report keys on an object that no scoped profile defines for its class.

severity{“Violation”, “Warning”, “Info”}, default “Violation”

The SEVERITY of every finding (triplets:lexicalForm stays Warning).

The PROFILE column lists the scoped section keys (["EQ", "OP", "SC"]).

triplets.validation.validate_schema_references(data, rdf_map, data_scope=None, rdf_map_scope=None, target_data_scope=None, target_rdf_map_scope=(), report_missing_targets=True, engine='auto', inheritance=True, undefined_namespace='http://iec.ch/TC57/CIM100#', severity='Violation', **kwargs)[source]¶

Check the reference types of the source instances’ associations.

Every instance in data_scope is checked on its own against the associations of its profiles (rdf_map_scope, merged); the referenced objects are looked up in that instance and the target_data_scope instances. A reference conforms when ANY type of its object is the range class or, with inheritance, one of its subclasses — the classes the source and target_rdf_map_scope profiles define. Findings are on source objects only.

data_scopeiterable of INSTANCE_ID, optional

The source instances; None = every instance.

rdf_map_scopeprofile identifier or sequence of them, optional

The source profiles — their associations are checked; None = the root entries.

target_data_scopeiterable of INSTANCE_ID, optional

Instances holding the referenced objects (e.g. the EQ for an SSH); None = every instance, [] = none (only the source itself).

target_rdf_map_scopeprofile identifier or sequence of them, optional

Profiles defining the referenced classes. A range class no source or target profile defines cannot be decided: the association is listed in skipped_shapes.

report_missing_targetsbool, default True

Report references whose object is in neither the source nor the target instances (triplets:missing); False leaves them silent.

inheritancebool, default True

False accepts the range class itself only.

severity{“Violation”, “Warning”, “Info”}, default “Violation”

The SEVERITY of every finding.
