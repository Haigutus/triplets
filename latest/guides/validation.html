Validation Architecture¶

Three validations¶

Validation is generic: the caller decides which instances and which schema profiles a run uses, and the core never reads instance headers — it works for any RDF loaded as triplets, CIM or not. Every input has a scope named after it:

Merged schema (schema_scope.scoped_rdf_map)¶

The listed profiles merge into one schema for the run — a CGMES 3.0 EQ file is ["EQ", "OP", "SC"]; a CGMES 2.4.15 EQ section already holds Core, Operation and ShortCircuit as published. Same-named entries combine:

  • Class parameters and inheritance lists: union.

  • Property cardinality: the lowest xsd:minOccours, the highest xsd:maxOccours (n = unbounded; a missing bound is no bound); multiplicity follows.

  • Attribute xsd:type: when the profiles differ (a definition without a type counts) the intended type is unknown — the key is left untyped and logged as an error. validate_schema does not check its datatype. Under validate_shacl its literals stay plain: pyshacl then reports an sh:datatype shape on such a key for every value, while the vectorized engines’ lexical check judges the text. The types compare expanded by the merged prefixes: xsd:float and http://www.w3.org/2001/XMLSchema#float agree.

  • Enumeration values: union.

An xsd:type outside the XSD namespace (cim:ActivePower) is checked by validate_schema as its base type: the xsd:type of the schema’s own entry for that datatype (named by the Attribute’s dataType, else the IRI’s local name — the CIMDatatype entry a bundle carries). Without one it is listed in skipped_shapes (SvPowerFlow.p: datatype cim:ActivePower has no xsd base type — not checked). A plain-literal type or base (xsd:string, rdf:langString) has nothing to check: no rule, no note. Neither has a language-tagged key (language, see export_schemas.md); a malformed tag, or a tag on a key with any other xsd:type, raises ValueError as in the export.

Datatype conflicts and types without an xsd base (not checked) are listed in the run’s skipped_shapes; relaxed cardinalities and united enumerations (checked, more loosely) in its relaxed_constraints, with one warning per run naming their count; each note quotes every profile’s own value (cardinality relaxed to 0..2 (DL: 1..1, DY: 0..1, GL: 1..2)). The merged ProfileMetadata keeps every profile’s identity: sections (the section keys, in scope order) and each field as a list in the same order (keyword: ["EQ", "OP", "SC"], versionIRI: [...]); the merged ProfileNamespaceMap holds the root’s and every scoped profile’s prefixes, bound as in the full schema (root first, then the profiles in schema order; first binding wins), so a prefixed xsd:type expands as in the full schema. A merged run is never stricter than running the listed profiles one by one: parameters only add, cardinality only relaxes. The shipped bundles merged whole ("*") differ in cardinality for 1–15 keys, in datatype only for CGMES 2.4.15 FH Model.version, and in enumeration values for 1–2 keys (NC).

Class inheritance (schema_scope.class_ancestors)¶

class_ancestors(rdf_map, rdf_map_scope) → {class: ancestor IRIs}: the same-named Class entries of the scoped profiles union their inheritance lists, and the relation is closed only through ancestors that have a Class entry of their own in the scope — another class’s list is never read as the parents of a class it mentions. Every engine gets this one map:

  • the vectorized engines widen sh:targetClass / sh:class through one class-membership index built from its (Type, ancestor) pairs per run (the IR is not fanned out): sh:targetClass Equipment hits Breaker;

  • pyshacl gets the same edges as rdfs:subClassOf in ont_graph (instance data is not mutated); the map is already closed, so pyshacl’s own closure adds nothing. Parents are the IRIs the schema records (https://cim.ucaiug.io/ns#IdentifiedObject for NC); a bare name resolves like rdf:type in the data graph (schema namespace, else undefined_namespace).

So the engines agree by construction. Each profile is its own world: NC SSI’s ACLineSegment list stops at Equipment, and SSI has no IdentifiedObject attributes — it reaches IdentifiedObject only when a scoped profile (ER) has an Equipment entry of its own. inheritance=False matches the exact rdf:type on every engine (pyshacl without ont_graph). Only sh:targetClass (target_by="Type") and sh:class widen; KEY / VALUE / ID targets pick exactly what they name, a SPARQL target exactly what its query selects in the data (the rdfs:subClassOf edges pyshacl gets in ont_graph are visible to a query that walks them on pyshacl only — no CGMES target query does). Schema class rules never widen: each Class entry already lists its inherited attributes. Identical findings are reported once (a property shape on both a parent and a child node shape, the same triple in two instance files).

Status & known limitations¶

Known engine gaps (those a run can detect land in its coverage metadata, skipped_shapes / skipped_components):

  • Vectorized engines walk sh:targetClass, sh:targetSubjectsOf, sh:targetObjectsOf, sh:targetNode and SPARQL targets (sh:target with sh:select; $shapesGraph / $currentShape are not bound). Shapes reached solely through a sh:target without sh:select (a sh:SPARQLTargetType instance, a JavaScript or other custom target) are invisible to polars/pandas/duckdb — compile() logs a warning naming them; use engine="pyshacl" for full spec coverage. sh:rule (SPARQLRule inference) is never applied by the vectorized engines; pyshacl applies it (advanced=True), so shapes with rules diverge by design — both land in skipped_shapes.

  • Property paths: direct, sh:inversePath, and the two-step sequence sh:path ( assoc rdf:type ) (the ENTSO-E “valueType” pattern — the constraint applies to the referenced object’s type; a dangling reference yields no value node per SHACL path semantics). Longer sequences and the *OrMorePath forms are skipped with a compile warning; engine="pyshacl" covers them.

  • Lexical datatype checks: datatype checks judge the raw lexical form of values; with lexical=True (the default) a valid but narrower form is a triplets:lexicalForm Warning — see the dedicated section below. engine="reference" always gives the pure pyshacl view.

  • sh:in compares text: the value’s lexical form (for an IRI, its local id) is compared with each member’s text, so the datatype is ignored — "1.0"^^xsd:float matches the member 1.0 (xsd:decimal). pyshacl compares typed RDF terms and reports a violation. CGMES sh:in lists hold IRIs (enumeration values), where both agree.

  • Numeric comparisons only: sh:minInclusive … sh:maxExclusive, sh:lessThan and sh:lessThanOrEquals compare values as numbers; a value (or pair) that is not a number — a date, a string — is reported as violating. pyshacl compares typed literals, so date/string comparisons agree only on engine="pyshacl" (#216).

  • A non-numeric range bound fails the compile: sh:minInclusive "2020-01-01"^^xsd:date (any range bound that is not a number) raises ValueError in compile(), so no shape is validated (#215).

  • sh:closed always allows Type: every triplets object carries rdf:type by construction, so the vectorized engines never report it on a closed shape; pyshacl reports it unless the shape lists rdf:type in sh:ignoredProperties. A deliberate divergence.

  • sh:nodeKind BlankNode(+combo) cases are intentionally not implemented in the vectorized engines (triplets data has no blank nodes).

  • sh:nodeKind follows the export schema: an Association / Enumeration path is IRI and an Attribute path Literal, whatever the text. For a KEY the schema does not declare (or without rdf_map) the vectorized engines guess from the text (iri.REFERENCE_LIKE: any-case UUID, scheme://…, urn:…, Name.attr, or an ID in the data), while the exported graph pyshacl sees uses the stricter export rule (absolute IRI or lowercase UUID → IRI) — the two can disagree on such keys.

  • The duckdb engine streams/spills by design, but a true larger-than-RAM validation has not been exercised yet.

Compile Once (shacl_ir.py)¶

Shapes are parsed by rdflib exactly once into CompiledShapes, cached by content hash of the shape sources:

shapes.ttl ──rdflib──► CompiledShapes
                        ├── graph  (rdflib shapes graph — what pyshacl consumes)
                        ├── ir     (flat constraint table — what the vectorized engines consume)
                        ├── hash   (content hash, the cache key)
                        ├── plans  {engine name → compiled artifact, filled lazily}
                        ├── deactivated  (shape ids switched off: the graph's sh:deactivated true)
                        └── active(deactivated_shapes) ──► CompiledShapes  (the run's rule set, cached per set)

The IR is a pandas DataFrame, one row per shape × target × constraint component. compiled.ir is inspectable (see examples/shacl_validation.py); the engine registries that consume it are internal.

Each value of a parameter is a constraint of its own (SHACL §4.1): two sh:node shapes, two sh:or lists or two sh:pattern values compile to two rows. One malformed shape does not stop the validation of the others (a non-numeric range bound does — see Known engine gaps). The compile runs these load checks, each one pyshacl refuses the whole shapes graph for (ConstraintLoadError / ShapeLoadError): a parameter taken once (sh:path, sh:minCount, sh:maxCount, sh:datatype, sh:nodeKind, sh:in, sh:minLength, sh:maxLength, sh:closed, sh:deactivated, sh:uniqueLang, sh:languageIn, sh:qualifiedMinCount, sh:qualifiedMaxCount) given twice, an empty sh:or / sh:and / sh:xone list, a non-literal sh:deactivated, sh:ignoredProperties without sh:closed, a declared sh:PropertyShape without sh:path. A shape that fails one is skipped and named in skipped_shapes with the reason (two sh:path values, two sh:in lists, empty sh:or list, sh:PropertyShape without sh:path); the rest compiles and validates. The skip is the malformed shape itself: a property shape alone, a node shape with its property shapes; a logical operator over it is dropped as over any skipped part, and so is a sh:node row whose target has nothing left (see below) — both decided at compile time. A malformed shape no targeted shape reaches is listed the same way. pyshacl validates a copy of the shapes graph without them: the malformed shapes’ triples, the references to them, the logical operators the compile drops over them and the sh:node rows whose target has only malformed parts left are removed, and skipped_shapes lists the same entries for them as the vectorized engines. pyshacl still refuses the graph for a malformed shape reached through sh:qualifiedValueShape (its owner keeps sh:qualifiedMinCount / sh:qualifiedMaxCount without the shape). sh:minInclusive and the other range parameters are not in the list: pyshacl evaluates every value.

The logical operators report one row per non-conforming focus node on a node shape (no KEY) and one per non-conforming value node in a property shape (VALUE = the value node), with the operator’s shape, severity and message. In a property shape, a member without its own sh:path takes the property’s path; a member with its own sh:path is a property shape over the value nodes (it compiles to a sh:node row of the property’s path). sh:and holds when every member does, sh:xone when exactly one alternative does; an empty (switched-off) alternative holds for every node.

Compile-time behaviors worth knowing: a NodeShape with several sh:targetClass (the ENTSO-E profiles do this) emits every row once per target class; shape reference cycles through sh:node / sh:or / sh:and / sh:not are detected, warned about, and dropped; supported sh:path forms are a direct IRI, sh:inversePath, the ( assoc rdf:type ) sequence, and sh:alternativePath only when every member resolves to the same one of these forms — one property in several namespaces, as the ENTSO-E profiles write it (any other path form warns and skips the property shape — pyshacl covers it). One walker compiles every shape — the targeted NodeShape, its property shapes, a shape referenced through sh:node, a member of sh:or / sh:and / sh:xone / sh:not: sh:closed, sh:sparql, sh:node and the logical operators on the NodeShape itself judge its focus nodes; a member or referenced shape with its own sh:property judges the same focus at node level. A property shape with its own sh:property runs those property shapes on its value nodes: below a sh:node target or a logical member (a shape judged for conformance) as a sh:node row — one finding per non-conforming value node, on the referring focus (SHACL §4.7.1); reached from the targeted NodeShape through sh:property only, as a sh:property row whose property shapes report their own findings on the value nodes (§4.7.2).

Terms no engine implements (sh:qualifiedValueShape, sh:qualifiedMinCount, sh:qualifiedMaxCount, sh:uniqueLang, sh:languageIn) compile to rows with params None: the engines skip them and the run metadata names them in skipped_components. A logical operator whose member the IR cannot express — such a term anywhere in it, a bare IRI with no shape triples, a part of it already skipped (a dropped operator, an inexpressible sh:path) — is not evaluated at all (judging the expressible part would fire on every focus node): the row is dropped and named in skipped_shapes, the shape’s other constraints still run. A value constraint declared on a node shape itself (sh:class, sh:in, sh:datatype, … judging the focus node) is not evaluated by the vectorized engines and is named in skipped_shapes. A sh:node row whose target has nothing left but skipped parts would conform on every node: it is dropped and named the same way (<shape>: sh:node target <target> not evaluated).

Every shape compiles, sh:deactivated or not. compiled.deactivated lists the shapes the graph declares sh:deactivated; compiled.active(deactivated_shapes) is the run’s rule set with exactly that argument switched off — None: the declared set, []: nothing (every shape runs, the declared ones included), a shape IRI or any list: it replaces the declared set. Rows whose lineage meets a switched-off shape are dropped; a switched-off sh:or / sh:and / sh:xone member or sh:node target empties and conforms, a switched-off sh:not shape empties and flags every node it judges (as pyshacl); under sh:closed a switched-off property shape’s path stays declared. The filtered compile is cached per set on the one compile: the compile’s hash, its own plans; with nothing declared and nothing chosen active() is the compile itself. Truthiness follows pyshacl (bool(literal.value)): true, a non-empty plain literal — so a plain "false" deactivates — or a non-zero number; "false"^^xsd:boolean and an ill-typed literal (no value) do not; a non-literal or a second value makes the shape malformed: it is skipped (see above). A malformed shape switched off is not evaluated and not listed; switched on, every engine skips it with the reason. An id that names no shape in the graph is logged as a warning. pyshacl validates a copy of the shapes graph carrying exactly the chosen set as sh:deactivated true when it differs from the declared one; the shapes embedded in the SHACL report carry the same flags. Rows that differ only in lineage (one property shape under two node shapes with a common target) run once. Each skipped_shapes entry carries its lineage too, so a switched-off shape takes its entries along; the operator drop rule is decided at compile time.

CompiledShapes.plans is where each engine caches its own compiled artifact (the polars/duckdb split_rules partition) — re-validating new data against the same shapes never recompiles anything.

Engine Contract¶

Every engine module implements:

validate(data, compiled: CompiledShapes, rdf_map=None, data_scope=None, ancestors=None, **kwargs) → violations DataFrame

rdf_map is the scoped, merged schema (scoped_rdf_map), ancestors the class_ancestors map (None = exact rdf:type). validate_shacl hands the engines compiled.active(...), the rule set with the switched-off shapes already removed; an engine called directly with the full compile validates them too.

  • pyshacl consumes compiled.graph without its malformed shapes (data goes through _rdflib_loader); ancestors becomes its ont_graph. Its report keeps the top-level results and drops the nested sh:detail explanations, one row per finding like the vectorized engines. A blank-node sh:resultPath (inverse, sequence or alternative path) reads as the KEY it resolves to.

  • pandas/polars/duckdb consume compiled.ir — they never touch rdflib and read the raw string VALUEs directly (rdf_map decides sh:nodeKind and types the graph of their sh:sparql and SPARQL target delegation); ancestors becomes the class-membership index.

  • sh:sparql IR rows: pyshacl evaluates them natively (advanced=True). The vectorized engines delegate them to triplets.sparql (auto order: qlever when built, else oxigraph when installed, else rdflib): the data is loaded into one dataset, each constraint runs as a single SELECT with the focus nodes bound via VALUES ?this {...} opening the WHERE group (the authored pattern starts from the focus nodes) and $PATH substituted from the IR, and max_workers=N runs the constraint queries in parallel: forked processes on rdflib (copy-on-write sharing of the dataset; threads don’t help rdflib — it is GIL-bound pure Python), threads on oxigraph and qlever (they release the GIL while evaluating over one shared store). Queries a strict engine rejects fall back to rdflib and do not run in parallel: a shapes file with many rejected queries can be slower with max_workers (GIL-bound fallbacks). For sh:sparql-heavy profiles build the qlever extension or pip install triplets[oxigraph]; the rdflib fallback runs in minutes. No query fixing: constraint queries run exactly as authored. A constraint query a strict engine rejects is reported as a triplets:invalidSparql Warning row naming the shape and is still evaluated on the lenient rdflib engine.

  • SPARQL targets (target_by="SPARQL") run the same way: each distinct target query once per run over the (scoped) data, its ?this column the focus nodes. A target query a strict engine rejects gets the same Warning row and is evaluated on rdflib; one no engine can run gives a triplets:invalidSparql Violation naming the NodeShape, which then has no focus; so does a query that projects no ?this. Every NodeShape sharing the query gets its own row. Prefixes come only from the sh:declare entries of the target’s sh:prefixes node (pyshacl also takes those of every owl:Ontology when that node declares none). A query matching a typed literal (md:Model.profile "…"^^xsd:anyURI in the Header shapes, cim:TransformerEnd.endNumber 3) matches only when the rdf_map scope types that KEY — pyshacl sees the same graph.

The Lexical-Form Datatype Deviation¶

A deliberate divergence from pyshacl. rdflib compares a literal’s declared datatype, so "1"^^xsd:float is simply valid — the vectorized engines see the raw lexical form and can judge it. Two levels:

SEVERITY

Warning

A nested datatype check (a member of sh:and / sh:or / sh:xone / sh:not, a shape referenced through sh:node) decides conformance on the lexical space only: "1" satisfies xsd:float there, as in pyshacl, and no Warning is reported for it. The sh:datatype of a property shape, also one reached through sh:property, reports the Warning.

The vectorized engines check both levels inline. pyshacl gets the pandas datatype check as a supplement (duplicates dropped on [ID, KEY, VALUE, VIOLATION_TYPE, SOURCE_SHAPE, SEVERITY]). validate_shacl(..., lexical=False) skips the triplets:lexicalForm level on every engine and pyshacl’s supplement; values outside the lexical space stay sh:datatype violations on the vectorized engines. Parity tests treat triplets:lexicalForm rows as documented extras: engines must never lose a violation pyshacl reports.

xsd:anyURI values are literals (the schema entry type decides, not the datatype), so they get the same lexical check: an IRI reference (RFC 3987, relative and non-ASCII allowed) — no controls, space, DEL or <>"{}|^`\, and % only as a %XX escape. "has space"^^xsd:anyURI is an sh:datatype violation on every engine; xsd:string stays unchecked.

rdf_map + rdf_map_scope matter for the pyshacl path: without them every literal VALUE is an untyped string (references that look like a UUID or absolute IRI stay IRIs), so sh:datatype xsd:float trips on everything; with them the N-Quads export attaches the scoped profiles’ xsd types and only genuinely broken values fail.

Every validation returns the canonical violations DataFrame — empty = conforms — identical across all engines:

What a finding found in the data (TARGET) is added by enrich.

Violations DataFrames export like any other DataFrame (export_to_csv, Excel, …), as a standard sh:ValidationReport (violations.shacl.to_shacl_report(...) — the exact inverse of the pyshacl report mapping in shacl_report.py) or as SARIF 2.1.0 (violations.shacl.to_sarif(...), see below). The SHACL report serializes via rdflib: format=None (default) derives the format from the path suffix (.ttl → turtle, .xml/.rdf → RDF/XML, …); an explicit format= always wins.

Every report export takes export_to_memory=True and returns BytesIO object(s) with .name instead of touching the filesystem — the same convention as export_to_cimxml/export_to_csv (to_csv returns a list: data file + sidecar).

Every message states its origin with a prefix, and the constraint text is never rewritten — raw sh:message / engine wording stays verbatim behind its tag. Exactly one of [shacl_message]/[engine_message] appears per result — the constraint text has one author:

Report size is controlled by existing dials, no dedicated flags: SARIF groups by default (group=True — repeated entries like [schema_class] appear once per rule, not per violation; group=False opts into the verbose per-violation form). The SHACL report cannot group (one sh:result per focus node is spec semantics), but every message entry is column-driven — drop a column (violations.drop(columns=["CLASS_DESCRIPTION"])) and its entry disappears; enrichment itself is opt-in.

The SHACL report additionally embeds the violated shapes’ defining triples (CBD, stamped by validate_shacl() into the run metadata), so sh:sourceShape is never an empty blank node — the sh:in list and every other constraint parameter are machine-recoverable from the report alone. SARIF carries the located line as the native region.snippet.text. All of this happens in the post-validate/context/locate passes — the engine hot path is untouched.

The validation stamps the message/engine distinction as a MESSAGE_SOURCE column (authored messages are known from the compiled IR); bare frames fall back to the violation-type namespace. The SHACL report carries the tagged entries as separate sh:resultMessages (results stay one per violation — merging them would break sh:ValidationReport semantics); SARIF carries them as newline-separated blocks in one message.text, adds [context_count] / [context_examples] blocks for grouped results, and puts the occurrence count in the rule title (SHACL Line completeness (8×) — the ruleId stays stable, so GitHub alert matching is unaffected).

enrich and locate preserve the attrs. On to_shacl_report, explicit report_source= / report_references= override the stamped values (plain labels — distinct from the sources= locate pass and the shapes object to_sarif(shapes=) takes). Frames without the attrs (bare frames, report_to_violations output) carry no run metadata in SARIF/csv/excel; the SHACL report node still gets prov:generatedAtTime (export time) and dcterms:creator — a standard report always says when and by what it was written.

Schema validation (validate_schema / validate_schema_references)¶

Validate data directly against the export schema (rdf_map) — no SHACL shapes needed, no rdflib on this path:

rdf_map = schemas.ENTSOE_CGMES_3_0_0_552_ED2
violations = triplets.validation.validate_schema(data, rdf_map, rdf_map_scope=["EQ", "OP", "SC"])
violations = data.shacl.validate_schema(rdf_map, data_scope=[eq_id], rdf_map_scope="EQ",
                                        engine="duckdb", report_undefined_keys=True)
references = triplets.validation.validate_schema_references(
    data, rdf_map, [ssh_id], ["SSH"], target_data_scope=[eq_id], target_rdf_map_scope=["EQ"])
references = triplets.validation.validate_schema_references(   # every loaded instance, source and target
    data, rdf_map, rdf_map_scope=["SSH"], target_rdf_map_scope=["EQ"])
compiled = triplets.validation.compile_schema(rdf_map, ["EQ", "OP", "SC"])     # cached
compiled = triplets.validation.compile_references(rdf_map, ["SSH"], ["EQ"])

validate_schema: per instance, against the merged scoped profiles. Every instance in data_scope is validated on its own (None = every instance). This is why the run is per instance: every CGMES 3.0 profile serializes IdentifiedObject.mRID 1..1 — a union frame carries duplicate mRID rows per re-declared object (false maxOccurs), while SSH’s own mRID requirement must be met by SSH’s own rows, not EQ’s. The checks are: cardinality from the resolved xsd:minOccours/xsd:maxOccours (incl. mRID — the schemas are profile-accurate: CGMES 2.4 declares it 0..1/not serialized, CGMES 3.0/NCP 1..1), datatype lexical checks from xsd:type, enumeration membership from values, and with report_undefined_keys=True keys an object carries that no scoped profile defines for its class (schema:domainIncludes). Class rules never widen to subclasses.

validate_schema_references: reference types against target instances and profiles. Each source instance’s associations (the source profiles, merged) are checked with the referenced objects looked up in that instance and the target_data_scope instances. A reference conforms when ANY type of its object (RDF types are cumulative) is the range class or, with inheritance, a subclass by class_ancestors over the source and target profiles. A range class none of those profiles defines cannot be decided: the association is listed in skipped_shapes. With report_missing_targets=True (default) a reference to an object in neither the source nor the target instances is a triplets:missing finding. Only associations stored in the source instance are reported — EQ and SSH share object IDs, so a target file re-declaring an object does not bring its rows into the source’s report.

severity= (both schema validations) sets the SEVERITY of every finding: "Violation" (default), "Warning" or "Info" — SARIF error / warning / note, sh:resultSeverity in the SHACL report; has_violation is False for a "Warning" or "Info" run. Any other value raises ValueError. triplets:lexicalForm findings are always Warning. validate_by_header forwards it to both runs.

The applied profiles land in attrs["validation"]["profiles"], each violation carries them as a list in the PROFILE column, reports carry [rdfs_profile] EQ, OP, SC entries, and SARIF alert titles read RDFS <profiles> <Class> <attr> (N×). Schema shape ids carry the scope in their namespace (urn:triplets:schema:EQ:OP:SC#Breaker.IdentifiedObject.name), so findings of different scopes never share a rule. The same vectorized engines run everything (plans cached per compiled schema); the pyshacl engine refuses schema-compiled IR. Results do not masquerade as SHACL: constraint language "rdfs", violation types xsd:minOccurs/xsd:maxOccurs/xsd:type/rdfs:range/schema:domainIncludes/ triplets:missing — real vocabulary IRIs in sh:sourceConstraintComponent, message tags [rdfs_expected], [rdfs_path], [rdfs_profile], …

CIM helpers (triplets.cgmes_tools)¶

The only code that reads instance headers, built on the generic calls:

from triplets import cgmes_tools

cgmes_tools.declared_profiles(data, rdf_map)        # {INSTANCE_ID: ["EQ"], ...}
violations = cgmes_tools.validate_by_header(data, rdf_map, references=True)

declared_profiles matches the header’s profile-identity fields (Model.messageType, keyword, Model.profile, conformsTo) against the schema profiles’ declared identity, with the legacy CGMES 2.4.15 profile-URL substrings as fallback; an identifier several profiles share matches none. validate_by_header runs validate_schema for each group of instances declaring the same profiles (merged), with references=True also validate_schema_references against every loaded instance and its declared profiles, and joins the runs with concat_violations. data_scope= selects the validated instances; references still resolve in every loaded instance. An instance whose header matches no profile is skipped and named in skipped_shapes; rdf_map_scope= overrides the declared profiles for header-less data.

Shared Loading (_rdflib_loader.py)¶

SHACL and SPARQL reach rdflib through the same load_dataset, so a validation and a query over the same data see an identical graph. SPARQL scopes after loading (scoped_graph); the pyshacl engine filters the rows to data_scope before loading, so data outside the scope is never exported or parsed:

Function

Produces

load_dataset(data, rdf_map=None, data_unchanged=False, store="memory", undefined_namespace=CIM_NS)

rdflib.Dataset seeing the deduplicated union, one named graph per INSTANCE_ID (urn:uuid:{INSTANCE_ID}). store="oxigraph" backs it with the oxigraph SPARQL engine’s cached store via oxrdflib ("auto": oxigraph when installed)

scoped_graph(dataset, data_scope=None)

full union when data_scope is None; otherwise a concrete Graph holding just the scoped instances’ named graphs (sparql.query’s data_scope, rdflib engine)

File Layout¶

triplets/
|-- _rdflib_loader.py        # shared with sparql: load_dataset()
'-- validation/
    |-- __init__.py          # validate_shacl / validate_schema / validate_schema_references, engine registry
    |-- schema_scope.py      # rdf_map_scope: profile resolution, merged schema, class_ancestors
    |-- schema_ir.py         # export schema -> CompiledShapes (compile_schema, compile_references)
    |-- shacl_ir.py          # shapes -> CompiledShapes (IR compiler, content-hash cache)
    |-- shacl_pyshacl.py     # reference engine: data + compiled.graph -> report
    |-- shacl_pandas.py      # compiled-IR executor (full registry; eager, debugging)
    |-- shacl_polars.py      # compiled-IR executor (lazy plans + collect_all, performance)
    |-- shacl_duckdb.py      # compiled-IR executor (SQL per constraint, larger-than-memory)
    |-- shacl_report.py      # ValidationReport <-> violations; multi-format export
    |-- context.py           # enrich (TARGET, instance/object/shape/schema context), concat_violations
    |-- locations.py         # violations -> source line/column (the sources= grep pass)
    '-- sarif.py             # violations -> SARIF 2.1.0 (grouped by default)

Usage¶

import pandas
import triplets
from triplets.export_schema import schemas

data = pandas.read_RDF(["grid.zip"])

# validate against a shapes file (format auto-detected by extension) — empty = conforms;
# the scoped profiles type the literals and give the class inheritance
rdf_map = schemas.ENTSOE_CGMES_3_0_0_552_ED1
violations = data.shacl.validate_shacl("shapes.ttl", rdf_map=rdf_map, rdf_map_scope=["EQ"])

# compile once, validate many
compiled = triplets.validation.compile(["equipment.ttl", "topology.ttl"])
violations = data.shacl.validate_shacl(compiled)

# one compiled base, shapes switched off per run (the NC validation aggregates):
# each set is filtered from the same compile and cached on it
base = triplets.validation.compile(base_shape_files)
violations = data.shacl.validate_shacl(base, deactivated_shapes=aggregate_off)

# data_scope filters to the named graphs (validated instances) — out-of-scope
# data is not loaded; include dependency instances for cross-instance references
one_instance = str(data["INSTANCE_ID"].astype(str).iloc[0])
violations = data.shacl.validate_shacl("shapes.ttl", data_scope=[one_instance])

# engines: auto is polars -> pandas -> pyshacl; works on any input flavor
data.shacl.validate_shacl("shapes.ttl", engine="pyshacl")      # or "polars" / "pandas" / "duckdb"
triplets.validation.validate_shacl(con, "shapes.ttl")          # DuckDB connection
violations = data.shacl.validate_shacl("shapes.ttl", lexical=False)   # no triplets:lexicalForm Warnings (pyshacl: the pure report)

# pyshacl on the oxigraph engine's cached store (identical results; opt in
# when the store is already loaded for SPARQL — Memory is faster otherwise)
data.shacl.validate_shacl("shapes.ttl", engine="pyshacl", store="oxigraph")

# the context pass, a separate call — TARGET (what was found), instance/file,
# object type/name, shape sh:name/sh:description and schema definition columns
violations = violations.shacl.enrich(data=data, shapes=compiled, rdf_map=rdf_map, rdf_map_scope=["EQ"])

# SARIF 2.1.0 for GitHub / SonarQube / any SARIF viewer
violations.shacl.to_sarif(path="report.sarif")

# standard sh:ValidationReport for SHACL tooling (format from path suffix,
# or format=); sources= adds an "[context_location] file line N" message per
# result (SHACL has no location vocabulary — plain-text messages travel
# everywhere); the dcterms metadata (timestamp, creator, data/shape file
# names) comes from violations.attrs — stamped by the validation, overridable
# with report_source=/report_references=
violations.shacl.to_shacl_report(path="report.ttl", sources=["grid.zip"])
violations.shacl.to_shacl_report(path="report.xml")  # RDF/XML via .xml
# rdf_map= expands sh:resultPath KEYs to their profile namespace
# (undefined_namespace for KEYs it lacks)
violations.shacl.to_shacl_report(path="report.ttl", rdf_map=rdf_map)

# tabular exports with the same metadata: CSV writes a report_meta.csv
# sidecar, Excel a second "metadata" sheet
violations.shacl.to_csv(path="report.csv")
violations.shacl.to_excel(path="report.xlsx")

# the location pass standalone — SOURCE_URI / SOURCE_LINE / SOURCE_SNIPPET columns,
# reused by both report exports
violations = violations.shacl.locate(sources=["grid.zip"])

pyshacl pass-through options (inference, advanced, store) are forwarded as keyword arguments. Names the schema does not declare (every name without an rdf_map) are written under undefined_namespace= (default CIM100, so schema-less cim: shapes keep working; the same parameter on validate_schema / validate_schema_references / to_shacl_report); every row is loaded. abort_on_first=True stops every engine at the first Violation (Warnings and triplets:invalidSparql never stop it), for a yes/no gate rather than a full report. Runnable end-to-end demos live in examples/shacl_validation.py (engine behavior walkthrough) and examples/shacl_reports.py (uv-runnable: performance engines + both report exports with source locations — uv run examples/shacl_reports.py).

Context enrichment (validation/context.py)¶

enrich(violations, data=, shapes=, rdf_map=, rdf_map_scope=, data_scope=) — a separate call after any validation — appends ENRICHMENT_COLUMNS to the report. Every source is optional; absent sources leave their columns null, so the output schema is stable. data_scope reads only those instances of data — pass the validation’s own scope so TARGET finds exactly what the run saw:

Columns

Source

Content

TARGET

data (+ shapes, rdf_map)

what the finding found: the referenced object’s id, Type and name — or that it is not in the data — for sh:class / reference-range / triplets:missing findings; the found type of a valueType row (needs shapes); the duplicate values of a maximum-count finding. A presented rdfs:range counts as a reference when its rule or the schema says the KEY is an Association

INSTANCE_ID, INSTANCE_LABEL

data

instance and its parsed file name (the Distribution/label meta rows)

OBJECT_TYPE, OBJECT_NAME

data

the focus object’s Type and IdentifiedObject.name

SHAPE_NAME, SHAPE_DESCRIPTION

shapes

sh:name / sh:description (a property shape inherits the parent NodeShape’s)

SCHEMA_DESCRIPTION, SCHEMA_MULTIPLICITY

rdf_map

the violated attribute’s schema definition in the profiles the violation was checked against — the PROFILE column, else rdf_map_scope (one scope, or {INSTANCE_ID: scope}), else the run’s attrs["validation"]["profiles"] — merged like the run (the multiplicity that was checked). Rows without profiles read the root entries; a name the profiles lack stays empty

CLASS_DESCRIPTION

rdf_map

the object’s class description

enrich reads no instance headers. Pass the same shapes object the validation ran with — anonymous property shapes get fresh blank-node ids per parse, so a re-parsed graph cannot be matched. An object present in several instances is attributed to its first occurrence.

SARIF 2.1.0 export (validation/sarif.py)¶

triplets.validation.export_to_sarif(violations, ...) / violations.shacl.to_sarif(...) — a spec-valid SARIF 2.1.0 log for GitHub, SonarQube or any SARIF viewer. Passing data=/shapes=/rdf_map= runs the enrichment pass first (an already-enriched frame is used as-is).

  • Grouped by default (group=True): a model can carry 100k identical findings that are really one issue — each rule becomes one result with occurrenceCount and the first-3 + last-3 sample instances (all listed when ≤ 6). group=False emits one result per violation row.

  • Severity maps Violation/Warning/Info → error/warning/note; rules carry the shape’s sh:description, and the rule title names the constraint language: SHACL <sh:name>, SHACL <attr> <violation type> for unnamed shapes, RDFS <profiles> <Class> <attr> for schema runs, (N×) appended when grouped; MESSAGE falls back to a generated text (message is mandatory in SARIF).

  • Every rule carries help (text + markdown, the panel GitHub shows under an alert), built from the group’s first finding and the run metadata: What this checks — the shape’s own sh:message, the path and the EXPECTED statement (verbatim, long value lists included); Schema context when enriched with the rdf_map — the property description with its multiplicity and the class description; Source — the shape IRI (http… shapes; also helpUri), the profiles of a schema run, the shapes file when the run used exactly one, and a link to the constraint’s definition (the SHACL spec section for sh:*, this page for triplets:*, the term IRI for xsd:/rdfs:/schema:). Lines without data are left out.

  • RDF objects carry no text coordinates through the triplets frame: results always point at the model via logicalLocations (Type/ID + object name). Passing sources= (the original CIM/XML files — paths, zips or file-likes) runs the shared locate_violations pass (validation/locations.py) and adds a fully bounded whole-line physicalLocation.region (startLine == endLine) on the violated property element’s line (or the object definition) — what GitHub code scanning needs to annotate lines. One grep-style pass per file; the parse/validate hot paths are untouched. A frame already carrying LOCATION_COLUMNS (from violations.shacl.locate(sources=...)) is used as-is. Without either, artifactLocation.uri falls back to the enrichment-traced file label, region-less. Positions are whole lines (1-based): RDF serializations put one statement per line, and a start-only region cannot be displayed by GitHub, so regions always carry startLine and endLine.

  • Everything domain-specific (triplet coordinates, schema descriptions, sample IDs) rides in the properties bags.

Naming Convention¶

Engine files follow {purpose}_{engine}.py, mirroring the parser and export modules. Shared loading lives in _rdflib_loader.py; the IR compiler in shacl_ir.py; the report normalizer in shacl_report.py.
